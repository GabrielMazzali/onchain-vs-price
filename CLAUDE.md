# CLAUDE.md

Contributor and architecture notes for this repository — what lives where and what to edit for common changes.

Research codebase: BTC + ADA daily on-chain signals (Coin Metrics) → supervised models (LR, XGBoost), plus an LSTM capacity-check stage. No packaged app; deliverables are notebooks, CSVs, and Parquet files.

## Environment & commands

- Python **3.12**, local venv at `.venv/` (gitignored). There is **no `requirements.txt`** — install deps manually.
- Activate (PowerShell): `.\.venv\Scripts\Activate.ps1`
- Currently installed: `numpy`, `pandas`, `pyarrow`, `scikit-learn` (1.9), `xgboost` (3.2), `coinmetrics-api-client`, `python-dotenv`, `requests`, `jupyter`/`nbconvert`. **`torch` is not installed** (LSTM stage not built yet). The loader also imports `blockfrost` for ADA staking.
- Install everything fresh:
  ```powershell
  pip install numpy pandas pyarrow scikit-learn xgboost coinmetrics-api-client python-dotenv requests jupyter blockfrost-python
  ```
- Batch-run the model notebooks (from repo root): `python utils\run_models_parallel.py` — re-executes 2a + 2b in parallel via `nbconvert`, writing `<name>_output.ipynb` next to each. LSTM is intentionally excluded.
- Run the ablation study (from repo root): `python utils\ablation.py` (~30 min; `--quick` for a fast 30d/1% XGB smoke test) — paired price-only vs +on-chain walk-forward, writes `data/ablation_results.csv` + `docs/results/ABLATION_RESULTS.md`. `pipeline\3_ablation.ipynb` just presents those results.
- Run model-free signal detection (from repo root): `python utils\signal_detection.py` (~2 min; `--quick` = fewer MI permutations) — lead-lag (Newey-West-corrected), hand-rolled Granger F-test, mutual information vs shuffle null, all FDR-corrected. Writes `data/signal_{leadlag,granger,mi}.csv` + `docs/results/SIGNAL_DETECTION_RESULTS.md`; `pipeline\3_signal_detection.ipynb` presents it. No `statsmodels` dependency (Granger/Newey-West hand-rolled with numpy+scipy).
- Run the volatility / regression test (from repo root): `python utils\volatility_test.py` (~14 min; `--quick` = XGB h=14 only) — paired price-only vs +on-chain regression on forward **log realized volatility** (Ridge + XGBoost), pooled OOS R² + Spearman corr + **non-overlapping** Wilcoxon (overlap-aware), plus a trending-vs-non-trending feature-driver analysis at 30d. Writes `data/volatility_{results,drivers}.csv` + `docs/results/VOLATILITY_RESULTS.md`.
- Run the cycle-timing test (from repo root): `python utils\cycle_timing.py` (fast) — MVRV/Puell/NVT expanding-percentile vs long-horizon forward returns (rank-IC with overlap-aware p, conditional returns, valuation-timing backtest vs buy-and-hold). Writes `data/cycle_timing_*.csv` + `docs/results/CYCLE_TIMING_RESULTS.md`.
- Run regime + event studies (from repo root): `python utils\regime_events.py` (fast) — KMeans regime clustering + event study around extreme on-chain readings. Writes `data/{event_study,regimes}.csv` + `docs/results/REGIME_EVENT_RESULTS.md`.
- Run the momentum backtest (from repo root): `python utils\momentum_backtest.py` (fast) — hold-above-MA rule (MA 7/14/30/50) for BTC/ADA, hit-rates + fee sweep (0/10/25 bps) vs buy-and-hold. Writes `data/momentum_backtest.csv` + `docs/results/MOMENTUM_BACKTEST_RESULTS.md`.
- Run the MVRV×sentiment test (from repo root): `python utils\mvrv_sentiment.py` (fast) — conditional forward returns by MVRV state × Fear&Greed state, horizons 90/180/365/540d (shows momentum wins short-term, valuation reverses at ~540d for BTC on ~1 cycle). Writes `data/mvrv_sentiment.csv` + `docs/results/MVRV_SENTIMENT_RESULTS.md`.
- Run/refresh a single notebook headless:
  ```powershell
  python -m jupyter nbconvert --to notebook --execute pipeline\2b_xgboost_model_pipeline.ipynb
  ```
- No test suite or linter is configured.

## Path conventions

`src/feature_engineering.py` defines canonical paths:
- `PROJECT_ROOT = Path(__file__).resolve().parent.parent`
- `RAW_DIR = PROJECT_ROOT / "data" / "raw"`
- `ENG_DIR = PROJECT_ROOT / "data" / "engineered"`

Notebooks under `pipeline/` add the repo root via `Path("..").resolve()` in the first `sys.path` cell. The EDA notebook uses `Path("../..")`. Never duplicate `RAW_DIR`/`ENG_DIR` constants in a notebook.

## Data flow (execution order)

1. `1_data_loader.ipynb` → pulls Coin Metrics via `CoinMetricsClient()` (community endpoint, **no API key**) → `data/raw/*.csv` → calls `engineer_features` + `save_engineered`. For ADA it also fetches per-epoch staking from **Blockfrost** (`fetch_blockfrost_ada_staking`), which needs `BLOCKFROST_PROJECT_ID` in `.env` (loaded via `python-dotenv`).
2. `2a` / `2b` → call `load_engineered_frames` (rebuilds from raw if engineered files are missing)
3. `eda_analysis.ipynb` → reads engineered frames for exploratory analysis

## Anti-leakage invariants (do not violate)

1. **No global scaling.** `StandardScaler` must be fit only on the training fold (`fit_scaler_on_train`), never on the full dataframe. XGBoost (2b) skips scaling entirely.
2. **No synthetic labels.** `classify_signal` returns `NaN` for `NaN` inputs — the caller's `dropna()` removes the last `h` rows. Never map `NaN → 0` (Hold).
3. **Inner CV uses `TimeSeriesSplit`.** `RandomizedSearchCV` inside each walk-forward fold must use `TimeSeriesSplit`, not shuffled K-Fold.

These three rules live in the model notebooks; `src/feature_engineering.py` is intentionally scaler-free.

## What to edit where

| Goal | Where |
|------|-------|
| Change features or forward-return targets | `src/feature_engineering.py` → `engineer_features` |
| Change label thresholds / signal logic | `src/feature_engineering.py` → `classify_signal` |
| Add/remove feature scaling columns | `src/feature_engineering.py` → `EXCLUDE_PREFIXES`, `EXCLUDE_COLUMNS`, `BINARY_COLUMNS` |
| Add a new asset (beyond btc/ada) | Extend `btc`/`ada` lists in loader + model notebooks; keep filenames consistent with path conventions |
| Add a new classical model | Copy walk-forward + MCC skeleton from `2b`; keep per-fold scaler + `TimeSeriesSplit` |
| Batch-run models | `python utils/run_models_parallel.py` from repo root |

## Key `src/feature_engineering.py` exports

- `engineer_features(df)` — builds lags, calendar flags, volatility, forward returns; computes asset-specific features only when source columns exist (BTC: exchange flows, Puell, hash rate; ADA: staking ratio); drops raw building blocks (`CapMrktCurUSD`, `TxCnt`, `asset`)
- `save_engineered(df, asset)` — writes CSV + Parquet to `ENG_DIR`
- `load_engineered_frames(assets)` — loads engineered CSVs, rebuilds from raw if missing
- `classify_signal(return_val, threshold)` → `{-1, 0, 1, NaN}`
- `get_feature_columns(df)` — numeric non-target non-binary columns safe for scaling
- `get_price_only_feature_columns(df)` / `get_onchain_feature_columns(df)` — the price-only subset (ablation Model A) and its complement; A is always a strict subset of the full set (`PRICE_ONLY_COLUMNS`)
- `fit_scaler_on_train(X_train)` — returns fitted `StandardScaler`; call inside fold only

## Known caveats

- Markdown "Final Analysis" sections in 2a/2b may quote stale MCC/F1 numbers from a pre-fix run; re-execute end-to-end to refresh.
- `data/engineered/` is gitignored; engineered files may be absent after clone and are auto-rebuilt from `data/raw/` on first `load_engineered_frames`.
- Coin Metrics API responses change over time; raw CSVs snapshot a specific date range.
